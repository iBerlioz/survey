# Форма записи на экзаменационную работу — Docker

Самостоятельный экспорт текущей формы. Содержит все 70 тем, тот же дизайн и логику выбора. Работает на Node.js 24 и SQLite без Sites, Cloudflare и внешних сервисов. В архив включены готовые клиентские файлы и их исходники.

## Запуск

Распакуйте архив на сервере, перейдите в каталог `presentation-survey-docker` и выполните:

```bash
cp .env.example .env
docker compose up -d --build
docker compose ps
```

Форма откроется по адресу `http://IP-СЕРВЕРА:8080`. По умолчанию порт 8080 слушает все сетевые интерфейсы. Для изменения порта задайте `HOST_PORT` в `.env`, затем выполните `docker compose up -d`.

Проверка и журнал:

```bash
docker compose ps
docker compose logs --tail=100 survey
```

## Домен и HTTPS

Если перед приложением стоит Nginx, Caddy или другой обратный прокси, укажите в `.env` внешний адрес формы, например:

```dotenv
PUBLIC_URL=https://survey.example.com
BIND_ADDRESS=127.0.0.1
HOST_PORT=8080
```

Проксируйте запросы на `http://127.0.0.1:8080` и выполните `docker compose up -d`. `PUBLIC_URL` должен соответствовать адресу, по которому участники открывают форму. Путь к форме — корень домена; развёртывание в подпапке не настроено. TLS обеспечивает ваш обратный прокси.

Если прокси находится в другом контейнере, подключите его к сети Compose и направляйте запросы на `http://survey:3000`; внешнее сопоставление `ports` можно убрать из `compose.yaml`.

## Логика

- ФИО — свободный ввод.
- Первые три формы экзаменационной работы ограничены восемью успешными записями каждая; отправка по почте без лимита.
- Третий вопрос показывает три случайные свободные темы и вариант «Своя тема». При новом заходе подборка создаётся заново. Проверка доступности каждые 15 секунд сохраняет варианты, пока они свободны.
- В конце круга, когда осталась одна или две темы, показываются только оставшиеся. После использования всех 70 тем начинается следующий круг.
- Тема и место закрепляются одной атомарной операцией: отправка двух форм одновременно не позволяет занять одно место сверх лимита или дважды выбрать тему в одном круге.
- Собственная тема, точно совпадающая с темой из списка, также участвует в бронировании.

## Данные

На первом запуске создаётся пустая база. Ответы, ранее собранные на Sites, в архив не включены: этот экспорт переносит приложение, а не удалённую базу. Старый сайт продолжит работать независимо; два сайта не синхронизируют записи и лимиты. После перехода распространяйте только новую ссылку.

Ответы находятся в именованном Docker-томе `survey-data` по пути `/data/survey.sqlite`. Перезапуск, пересоздание контейнера и `docker compose down` без `-v` сохраняют ответы. `docker compose down -v` удаляет том вместе с данными.

Просмотр ответов с сервера без публичного административного интерфейса:

```bash
docker compose exec -T survey node export.mjs --json
```

Выгрузка CSV для Excel, разделитель — точка с запятой:

```bash
docker compose exec -T survey node export.mjs > responses.csv
```

Даты хранятся в UTC. Выгрузка содержит ФИО, форму экзаменационной работы, тему, дату и номер круга. В открытой форме добавлен поиск ответов по полному ФИО: показываются все совпадающие записи без ID. Регистр и повторные пробелы не учитываются; частичный поиск не поддерживается. Любой, кто знает полное ФИО, может увидеть такие ответы.

Для резервной копии базы остановите приложение, скопируйте содержимое тома и запустите снова. Для просмотра точного имени тома:

```bash
docker compose config --volumes
```

Не копируйте только SQLite-файл во время записи: актуальные изменения могут находиться в соседнем WAL-файле.

## Изменения и сборка

Готовые `public/app.js` и `public/styles.css` уже включены, установка npm-зависимостей для Docker не требуется. В образ копируются только серверные файлы и готовый интерфейс.

- `src/App.tsx` — исходник формы;
- `src/options.ts` — темы и форматы для интерфейса;
- `options.json` — темы и форматы для сервера;
- `database.mjs`, `booking.sql` — хранение, лимиты и бронирование;
- `server.mjs` — HTTP-сервер;
- `public/styles.css` — оформление.

При изменении тем или форматов обновляйте одновременно `options.json` и `src/options.ts`. Для пересборки интерфейса нужен Node.js 24:

```bash
npm install
npm run build
npm test
docker compose up -d --build
```

Переименование уже использованных тем или форматов требует отдельной миграции ответов, чтобы сохранить правильные счётчики. Для нового учебного потока используйте отдельный проект Compose и новый том.

## Проверка экспорта

Приложение проверено непосредственно на Node.js 24: HTTP-ответы, параллельные заявки с лимитом 8, единственное бронирование темы, переход к новому кругу, сохранение ответов после перезапуска, кириллица, отклонение запроса с постороннего сайта. Docker CLI в среде подготовки отсутствовал; сборка образа и запуск Docker Compose здесь не выполнялись.

## Админка на отдельном порту

Админка работает в том же контейнере, читает ту же базу и слушает внутренний порт 3001. Compose публикует её по адресу `127.0.0.1:8081`; публичная форма остаётся на 8080. В админке: таблица ответов, поиск по ФИО/теме, фильтр формы экзаменационной работы, счётчики мест, CSV и JSON. Обновление каждые 15 секунд. Добавлены исправление ФИО, формы экзаменационной работы и темы, а также полное удаление записи с подтверждением. Исправление проверяет лимит мест и занятость темы.

Пароля в приложении нет. Ограничение по IP выполняет ваш Nginx для всего административного виртуального хоста, включая API и выгрузки. Админку подключайте к корню отдельного домена, например `survey-admin.example.com`либо в локацию /admin (ниже) 

Пример административного виртуального хоста Nginx (замените домен и IP):

```nginx
server {
    listen 80;
    server_name survey-admin.example.com;

    #allow xx.xx.xx.xx;
    deny all;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Если Nginx уже настроен на HTTPS, используйте существующие настройки сертификатов. `allow`/`deny` размещены на уровне `server`, чтобы защищать и страницу, и API, и скачивание файлов. Если перед Nginx стоит другой прокси, настройте определение реального IP для доверенного прокси.

Для Nginx в отдельном контейнере используйте ту же Docker-сеть и `proxy_pass http://survey:3001`; порт админки на хост можно вообще не публиковать.

### Обновление ранее запущенной версии

Распакуйте обновлённый архив поверх файлов в **том же каталоге проекта Compose**. Существующий `.env` сохраните: в архиве только `.env.example`. Затем:

```bash
docker compose up -d --build
docker compose ps
```

Имя Compose-проекта и тома не меняйте; `docker compose down -v` не выполняйте. Ответы сохранятся в прежнем томе.

Проверка административного API с самого сервера:

```bash
curl http://127.0.0.1:8081/api/responses
```

Проверено: чтение ответов и CSV/JSON доступны на административном порту; на публичном порту эти маршруты возвращают 404. Docker-сборка в среде подготовки не выполнялась.

## Обновление с редактированием и поиском

После отправки форма показывает ФИО, форму экзаменационной работы и тему. Ниже доступно «Посмотреть ранее внесённое» с поиском по полному ФИО. Совпадение полного ФИО не удостоверяет личность; записи однофамильцев с одинаковыми ФИО показываются вместе.

Кнопки «Исправить» и «Удалить» находятся в строках административной таблицы. Изменения сохраняются в текущую базу, исходная дата записи сохраняется. В форме редактирования тему можно вписать вручную. Бронирование темы остаётся в круге исходной записи; лимит выступлений проверяется при сохранении. При удалении требуется подтверждение с данными студента. Административные изменения доступны только через порт 3001.

Админка поддерживает `/admin/` с относительными ссылками. В Nginx достаточно следующего блока, прежние директивы `sub_filter` можно удалить:

```nginx
location = /admin {
    return 301 /admin/;
}
location ^~ /admin/ {
    #allow xx.xx.xx.xx;
    deny all;
    proxy_pass http://127.0.0.1:8081/;
    proxy_set_header Host $host;
}
```

Замените IP на разрешённый адрес. В `.env` оставьте `PUBLIC_URL=https://survey.example.com`. Административные операции проверяют Origin; этот адрес должен соответствовать адресу сайта в браузере. Прежний Nginx-конфиг с `sub_filter` также совместим: относительные ссылки не требуют подмены.

Для обновления распакуйте файлы поверх **того же** каталога проекта и выполните `docker compose up -d --build`. Существующий `.env` и имя проекта Compose сохраните. Удалять том не нужно. Ответы не включены в архив: существующие данные остаются на вашем сервере.

Проверено на Node.js: редактирование освобождает слот; перевод в заполненное выступление отклоняется; удаление освобождает тему; поиск по полному ФИО возвращает записи без ID; публичный порт не принимает административные изменения. Docker в среде подготовки отсутствует.

## Общий список студентов и сдача работ

В админке появился раздел «Общий список студентов». Он хранится в той же SQLite-базе в новой таблице `students`, которая создаётся автоматически при запуске обновлённой версии. Существующие ответы и том не изменяются и не удаляются.

Загрузите CSV UTF-8 (в Excel: «CSV UTF-8»), не более 2 МБ и 5000 строк. Поддерживаются запятая или точка с запятой, BOM, CRLF, кавычки и экранированные кавычки. Обязателен столбец `ФИО`. Необязательный столбец `Работа сдана` принимает `Да`/`Нет`, `1`/`0`, `TRUE`/`FALSE`. Пример — `students.example.csv`:

```csv
ФИО;Работа сдана
Иванов Иван Иванович;Да
Петров Пётр Петрович;Нет
Сидорова Анна Сергеевна;
```

Импорт дополняет список и обновляет совпадающие ФИО. Студенты, отсутствующие в новом файле, остаются в базе. Пустой или отсутствующий статус сохраняет прежнюю отметку; у нового студента по умолчанию «не сдано». Явное `Нет` снимает отметку. Результат импорта показывает количество добавленных, обновлённых и объединённых повторов ФИО в файле. При ошибке файла импорт целиком отклоняется.

Сопоставление с ответами выполняется по полному ФИО без учёта регистра и повторных пробелов. Порядок частей ФИО, инициалы, опечатки, `е`/`ё` автоматически не исправляются. Совпадающие ФИО в общем списке объединяются; различать полных тёзок по одному ФИО невозможно. Противоречивые статусы одинакового ФИО внутри файла вызывают ошибку.

Таблица показывает выбор темы и все совпавшие записи студента, включая дубли. Фильтры позволяют увидеть тех, кто не выбрал тему, не сдал работу либо уже сдал. Чекбокс «Работа сдана» сохраняет отметку на сервере, в том числе для студентов без выбранной темы. Отметка сдачи привязана к студенту из общего списка, а не к одной из его записей выбора темы. При исправлении ФИО в ответе сопоставление пересчитывается.

Кнопка «Выгрузить общий список CSV» выгружает всех студентов общего списка со столбцами `ФИО`, `Работа сдана`, `Тема выбрана`, `Темы`. Можно изменить статусы в этом файле и загрузить его обратно; дополнительные столбцы при импорте игнорируются. Обычные выгрузки ответов остаются отдельными. Студенты, не включённые в общий список, видны в прежней таблице ответов, но не входят в счётчики общего списка.

Данные общего списка и изменение сдачи доступны только на административном порту. Поиск в открытой форме не раскрывает общий список и статус сдачи. Для Nginx на `/admin/` дополнительная настройка не требуется. Сохраните существующий `.env` и имя Compose-проекта, затем выполните `docker compose up -d --build`. Для нового учебного потока используйте отдельную базу/том, как и раньше.

## Вкладки админки, оценки и исправление общего списка

Админка разделена на две вкладки: «Общий список» (импорт, сверка, сдача, оценки) и «Выбранные темы» (прежняя таблица ответов с фильтрами, исправлением и удалением). При открытии показывается общий список. Стрелки влево/вправо и Home/End переключают вкладки с клавиатуры. Выгрузки ответов CSV/JSON видны на вкладке тем; выгрузка общего списка остаётся на его вкладке.

У каждого студента есть поле «Оценка» и кнопка «Сохранить оценку»; Enter тоже сохраняет. Допускается число или короткая текстовая отметка до 32 символов. Конкретная шкала не навязывается. Пустое значение при ручном сохранении удаляет оценку. Оценка и отметка «Работа сдана» независимы. Фильтр «Без оценки» показывает ещё не оценённых студентов.

CSV общего списка поддерживает дополнительный столбец «Оценка». Пустая или отсутствующая оценка при импорте сохраняет прежнюю; непустая обновляет её. Общая выгрузка включает оценки и подходит для повторного импорта. Пример:

```csv
ФИО;Работа сдана;Оценка
Иванов Иван Иванович;Да;8
Петров Пётр Петрович;Нет;
```

Кнопка «Исправить» в общем списке позволяет изменить ФИО, оценку и сдачу. При исправлении ФИО все ранее совпавшие по нормализованному ФИО записи выбора темы переименовываются в одной транзакции, чтобы сохранить связь. Если новое ФИО уже есть в общем списке, исправление отклоняется без изменений; автоматического объединения студентов нет. Существующее правило о полных тёзках остаётся: по одному ФИО невозможно различить разных людей.

Кнопка «Удалить» удаляет студента только из общего списка, вместе с его оценкой и отметкой сдачи. Перед действием показывается подтверждение. Записи о выбранных темах и занятые места сохраняются; удалить такие ответы можно отдельно на вкладке «Выбранные темы». Повторный импорт удалённого ФИО создаст студента заново.

При запуске обновления в таблицу students автоматически и однократно добавляется столбец grade; ФИО, выбранные темы и прежние отметки сдачи сохраняются. Новый код требует пересборки контейнера (`docker compose up -d --build`) и обновления страницы админки. Сохраните прежний Docker-том и имя Compose-проекта. Ручная миграция и изменение Nginx не требуются.
